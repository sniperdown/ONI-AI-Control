## 五、`/v1/buildings` 性能 —— ✅ 结论颠覆了最初假设

```
冷启动第1次：HTTP 692ms   mod 6ms    totalItems=72792
热态 5 次：  HTTP 303/62/89/63/52 ms   mod 恒 5ms
limit=2000&offset=20000 → mod 13ms  scanned=22000
全量分页：37 页 × ~200ms = 7.5 秒拿到 72792 条
```

`timing = {loopMs:5, visMs:0, nameMs:0, jsonMs:0}` —— **四段全是个位数**。

**三个假设全灭**：
1. ❌ “数据量大” —— 全量 72792 扫一遍才几十毫秒
2. ❌ “首轮开销”（STRINGS/PlainText 懒加载） —— `nameMs` 恒为 0
3. ❌ “迷雾过滤导致小 limit 也扫全表” —— `filteredByFog = 0`，而且 `scanned` 与 `limit` 严格相等

**真因**：`MainThread.Invoke(..., 5000)` **排队超时**。游戏刚加载完 75 MB 存档，主线程在忙渲染，action 在队列里等了超过 5 秒。HTTP 线程抛 504，但**队列里的 action 后来照跑并打了日志** —— 所以“日志行存在”只证明 Query 最终跑了，**不证明它在 5 秒内跑了**。

**修法（0.39.0 已写，未打包）**：自适应超时（主线程忙给 30s）+ `503 RETRY_LATER` + `Retry-After: 1` + 结构化 `details`。

## 六、卡住的地方：模组差异对话框

加载这个存档时游戏弹出 **「模组差异」**（`SAVE_GAME_MODS_DIFFER`，Klei 官方 `ConfirmDialogScreen`），列出约 20 个“先前未启用”的工坊模组（Queue For Sinks、DGSM、AI Improvements、True Tiles、Fast Save、Build Over Plants、Decor Pack I、ONI AI Bridge 等）。

**这个对话框对所有合成输入无反应**，以下全部试过、全部无效：
- 窗口消息点击（4 次，含修正坐标后）
- 先 hover 再点
- 双击
- `Enter`
- `Tab` + `Enter`
- `Space`
- **`SendInput` 硬件级模拟**（坐标已 1:1 核对：按钮在屏幕 y 1440–1475、x 1730–2130，点 (1920,1462) 正中）

而**主菜单的「继续游戏」用同样的方式一按就进** ⇒ 不是坐标问题，不是输入方式问题，是这个 `KScreen` 的输入通道。

**后果**：游戏一直 `isPaused: true`，`/v1/command {"op":"resume"}` 返回 `409 NOT_APPLIED`（`requested isPaused=False but game reports True`）。

**结论：只能由人手点「好的」。** 这条以后每次测同一个存档都会遇到。
